# Timing Sentinel A7 0.4.9 · 精简工作台

完整解压后运行TimingSentinelA7-SPI.exe；无需安装Python/Vivado。EXE旁的_internal、licenses和其他文件保留。软件未签名，不关闭系统安全措施。正常使用配合已固化USR43与STM32真实FIR/IRQ固件，不重新烧录。

## 常用操作

1. 选实际CH340串口，点“连接设备”。COM编号会随电脑/USB口变化，不选蓝牙串口。数据线优先直接连接稳定USB口。
2. 按蓝色按钮和左侧提示操作：设备中已有记录时先“读取板端记录”，再保存；设备就绪时可开始实验。连接本身不启动新采集。
3. 左侧选择下一次实验期限，点“开始实验”。3.5ms演示重负载超期；8ms作正常对照。程序自动保护旧冻结记录、提交并回读配置、采集三档各2次、逐份保存；末轮保留板端证据。
4. 看上方判定/GPIO/SPI卡片和波形；点“查看实验报告”读完整六任务统计。上方卡片对应当前显示记录，不是左侧尚未执行的下一次设置。“符合演示预期”不把TIMEOUT改成PASS。
5. “保存记录”保存tscap；保存后“打开目录”定位实际文件。“保存位置”影响下次默认目录，不搬移旧文件。未保存的实物记录不能被再次读取直接覆盖。“导出数据”可导出JSON、CSV、VCD，但不能代替原始tscap。
6. “打开记录”为历史回放，不控制板端。默认仅显示“关键事件、规则详情、批量统计”。“高级配置与诊断”中仍保留完整事件、原始数据和通信日志。
7. 高级配置包含规则/采样/配置提交回读、单次ARM、停止、保存后释放。它们仍受原安全门禁限制。断开重连不能把旧回放当作当前板端已保存证据。

## 同次四规则展示（仅波形）

选择“3.5 / 8 ms · 仅波形”后开始实验：同一次UART A5事件同时启动四条规则，R0/R1分别检查GPIO的3.5/8ms期限，R2/R3分别检查SPI C3的3.5/8ms期限。重负载记录可出现TIMEOUT/PASS/TIMEOUT/PASS，说明同一实际响应在不同期限下的判断不同，不是四次独立任务。实际结果以记录为准。

此模式不启用板端判定声光，属于正式固件的保护边界，不需要重新烧录。需要灯光和蜂鸣器演示时，使用原3.5ms或8ms模式。随包同次对照记录仅用于历史回放，不代表当前板端状态。

## 状态与边界

- “采集已完成 · 板端记录保留”对应FROZEN，是保护证据，不是卡死。下次实验会先保护并保存旧记录，成功后再释放。
- “尚未保存”须先保存。部分数据/未知连接状态不能当完整通过；缺失响应显示“—”而不是0。
- UART起点为合法停止位中心校验通过，SPI终点为第8采样沿；时间轴ms/μs是显式显示换算，不改原始tick和导出数据。
- 历史记录、模拟数据和实物读取分开显示；时间按50MHz标称时基换算，逻辑20ns/tick，波形采样间隔由采样配置决定，非连续无盲区采集。
- 三档任务按编号轮换，不保证第一轮必是无中断，但有效连续六轮每档各2次。默认板上KEY0仍是2ms旧窄窗，异常灯/三声不等于运算错误。
- 默认隐藏并禁用旧六场景入口。只有断开设备、没有未保存实物记录且本窗口未识别过真实任务时，才能在“通信日志”勾选“旧六场景固件调试（高级）”，并明确确认警告；此操作只改变GUI模式，不识别或刷写STM32。启用后真实任务按钮停用；识别到真实任务会撤销旧模式。当前FIR/IRQ固件不要启用该模式。
- 出错先保留截图、实验目录和原始文件，不反复ARM、RESET、释放或重刷。设备与诊断/通信日志保留完整提示。

此上位机包不是完整比赛源码重建包。真实硬件资格、同版长测和第二电脑检查分别记录，不把回放或软件自测当成新的板级实测。

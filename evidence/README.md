# 验证证据附件

这里提供既有正式USR43与临时ILA实验的可复核附件，不是新增上板测试。固件、应用和原始文件未修改；本次只做历史文件绑定、公开路径整理及离线复核。

## 从哪里看

| 目录 | 内容 | 可说明什么 |
| --- | --- | --- |
| fpga/ | 综合/实现利用率、时序、默认DRC、十组行为仿真日志、网表功能摘要 | 正式源/bit的资源与实现质量；仿真与上板资格分开 |
| soak600/ | 两窗口原统计及历史验收摘要 | 三档负载×两窗口，各100个受控FIR任务，不是六类合成故障 |
| records/soak600/ | 600份原始tscap，各任务一份，job9至608 | 可回放与从原始电平重判；未把保存副本重复计数 |
| ila/ | 12组原始CSV与tscap、调试实现摘要、一次被拒绝的旧配对说明 | 内部事件/时间戳对应；临时镜像与正式镜像不是同一个bit |
| flash/ | 整片擦写/读回、真正断电及按键摘要 | 编程当时与随后冷启分别留证，不回填旧快照 |
| records/coldboot/ | 最终正式镜像真正断电后的冻结记录 | 对应人工供电操作及后续只读核验，不是软件重下载 |
| software/ | 已封存的435项上位机离线测试摘要 | 源码回归，不冒充实物600任务 |

`index.json`连接事务身份与文件，`manifest.json`封存公开附件的字节数/SHA256，`provenance.json`记录所选原件哈希与公开件变换。JSON摘要选择原件字段，不替代原始完整资格文件；未选字段不表示值已改变。报告仅遮盖主机名和本机路径，技术数值、警告与错误不抹除。二进制波形和CSV保持原字节。原始完整记录和路径绑定保留本机，不公开无关个人数据。

## 如何复核

在配套工程根目录执行（Python标准库即可）：

```text
python -B scripts/verify_evidence.py
python -B scripts/verify_evidence.py --replay
```

第一条核对全部文件、600份记录内部成员、身份、分组、规则及12组ILA深度。第二条另外使用配套`host/`中的既有离线译码器，对600份原始样点重新解码和核对负载身份；这不是600次新实物实验。

若单独下载附件ZIP，使用`python -B scripts/verify_evidence.py --root evidence`做第一条检查；全样点重判需同时取得同版工程，显式提供`--host <工程的host目录>`。脚本不打开串口/JTAG，不编程，不释放记录，也不自动修改原始输入。

## 版本与条件

正式bit的SHA256为`b18e94908531ebf2f0218c375f78d815290fbebb554a1c51848f50e4c12a3636`，USR_ACCESS为4D565043。片内观察使用494C4131临时镜像，不能把其资源表或调试警告写成正式版指标。

600任务采用5MS/s、标称50MHz时基、UART115200及SPI mode0/250kHz。READY控制任务，采集与上传有等待空档。ILA采用稀疏事件限定捕获，时间间隔按探针中的48位tick解释，不按相邻CSV行计算。

正式版已约束路径WNS3.346ns、WHS0.055ns，默认DRC零项；不据此宣称所有外部端口都有时序预算或完成形式化证明。临时ILA默认有4项Warning，原摘要保留。普通单期限模式有声光，同事务四规则模式仅波形；默认KEY0为2ms期限，与GUI3.5/8ms实验设置不同。

Flash原阶段摘要中的`physical_power_cycle_verified:false`是编程当时的快照，真正断电证明在独立coldboot摘要中；二者不矛盾。本次重新检查了两份16MiB读回的哈希、擦除FF、有效载荷及尾部FF，但不重复分发32MiB读回文件，更不表示本次又擦写过Flash。
